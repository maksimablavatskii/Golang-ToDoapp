# Golang ToDoapp

REST API для учёта задач пользователей. Сервис позволяет создать пользователя, добавить ему задачи, отмечать их выполненными и получать статистику: сколько задач создано и завершено, каков процент выполнения и сколько в среднем занимает работа над задачей.

Проект подойдёт как пример небольшого Go-сервиса с PostgreSQL: HTTP-запрос проходит через обработчик, бизнес-логику и репозиторий, после чего данные сохраняются в базе. В репозитории есть SQL-миграции, Docker Compose для запуска и интерактивная документация API.

## Возможности

- Создание, просмотр, изменение и удаление пользователей.
- Создание, просмотр, изменение и удаление задач. Каждая задача принадлежит пользователю.
- Фильтрация задач по автору и постраничная выдача через `limit` и `offset`.
- Отметка задачи как выполненной или повторное открытие; время завершения обновляется автоматически.
- Статистика по всем задачам или по отдельному пользователю за выбранный период.

## Быстрый запуск

Понадобятся Docker с Compose, GNU Make и оболочка с POSIX-командами (на Windows подойдёт Git Bash). Для запуска в контейнере устанавливать Go отдельно не требуется.

1. Скопируйте `.env.example` в `.env` и заполните `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Например, для локального запуска можно задать всем трём переменным значение `todoapp`. Файл `.env` не отслеживается Git.
2. Из корня проекта выполните:

   ```bash
   make env-up
   make migrate-up
   make todoapp-deploy
   ```

   Первая команда запускает PostgreSQL, вторая создаёт таблицы, третья собирает и запускает API. Если миграция не смогла подключиться сразу после запуска базы, дождитесь её готовности и повторите `make migrate-up`.

3. Откройте [Swagger UI](http://localhost:5050/swagger/). Адрес API — `http://localhost:5050/api/v1`; спецификация также хранится в [docs/swagger.yaml](docs/swagger.yaml).

Для остановки приложения и базы: `make todoapp-undeploy`, затем `make env-down`. Данные PostgreSQL сохраняются в `out/pgdata` и остаются после остановки контейнеров.

## Как пользоваться API

Все методы API начинаются с `/api/v1` и возвращают JSON. Для `POST` и `PATCH` передавайте заголовок `Content-Type: application/json`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/users` | Создать пользователя |
| `GET` | `/users`, `/users/{id}` | Получить список или одного пользователя |
| `PATCH` | `/users/{id}` | Изменить пользователя |
| `DELETE` | `/users/{id}` | Удалить пользователя |
| `POST` | `/tasks` | Создать задачу для пользователя |
| `GET` | `/tasks`, `/tasks/{id}` | Получить список или одну задачу |
| `PATCH` | `/tasks/{id}` | Изменить задачу или её статус |
| `DELETE` | `/tasks/{id}` | Удалить задачу |
| `GET` | `/statistics` | Получить статистику по задачам |

Пример работы: сначала создайте пользователя и возьмите `id` из ответа, затем используйте его в `author_user_id` при создании задачи.

```bash
curl -X POST http://localhost:5050/api/v1/users \
  -H 'Content-Type: application/json' \
  -d '{"full_name":"Иван Иванов","phone_number":"+79998887766"}'

# Подставьте ID созданного пользователя вместо 1.
curl -X POST http://localhost:5050/api/v1/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Купить продукты","description":"Молоко и хлеб","author_user_id":1}'

# Подставьте ID созданной задачи вместо 1.
curl -X PATCH http://localhost:5050/api/v1/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"completed":true}'

curl 'http://localhost:5050/api/v1/statistics?user_id=1'
```

При создании задача получает статус `completed: false` и время `created_at`. Когда `completed` меняется на `true`, сервис записывает `completed_at`; при возврате к `false` очищает его. В `PATCH` можно передать только нужные поля. Для очистки необязательного `description` передайте JSON `null`.

`GET /tasks` принимает необязательные параметры `user_id`, `limit` и `offset`. `GET /statistics` принимает `user_id`, `from` и `to`. Даты задаются в формате `YYYY-MM-DD`; период отбора задач определяется по `created_at`, включая `from` и исключая `to`. Ответ статистики содержит `tasks_created`, `tasks_completed`, `tasks_completed_rate` (процент) и `tasks_average_completion_time`. Если задач нет, последние два поля равны `null`.

## Устройство проекта

```text
cmd/todoapp/       точка входа и сборка приложения
internal/core/     конфигурация, HTTP-сервер, общие типы и подключение к БД
internal/features/ обработчики, сервисы и PostgreSQL-репозитории для users, tasks, statistics
migrations/        SQL-миграции схемы todoapp
docs/              спецификация OpenAPI и файлы Swagger
postman/           коллекция запросов для ручной проверки API
```

Сервис написан на Go, использует `net/http` для маршрутов и `pgx` для PostgreSQL. Конфигурация берётся из переменных окружения; образец находится в `.env.example`. При завершении процесса HTTP-сервер корректно закрывается с тайм-аутом `HTTP_SHUTDOWN_TIMEOUT`.
